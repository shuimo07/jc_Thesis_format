## 1. 封面下划线填充线

封面字段要求「一整条连续下划线，字段值居中落在线上」。这看起来最简单，实际最容易返工。

### 问题一：行尾空白不画下划线

Word **不会**给段落末尾的空格画下划线。所以「标签 + 一堆带下划线的空格」这种写法，
右半段的下划线会**整段消失**。

**解决**：右侧改用**右制表位 + 下划线前导符**（`w:leader="underscore"`）。
制表位前导符不会被吞。

### 问题二：制表位居中 + 前导符会在文字两侧留缝

如果用一个「居中对齐的制表位 + 前导符」把字段值顶到中间，参考模板里那种紧贴文字的效果
出不来——前导符会在文字两侧各留约半个字的空档。

**解决**：混合方案。

| 位置 | 做法 | 原因 |
|---|---|---|
| 左侧填充线 | **带下划线的空格 run** | 紧贴文字，不留缝 |
| 字段值 | 不加下划线的普通 run | 值在线上，但线不穿过字 |
| 右侧填充线 | **右制表位 + `underscore` 前导符** | 尾部空白不会被吞 |

### 问题三：多出半个字符宽就折行

填充宽度要**向下取整**。算式：

```
可填充宽度(em) = (版心右缘 - 填充起始) / 14pt 的 em 宽度
左侧空格数     = floor((可填充宽度 - 字段值宽度(em)) / 2 / 0.5)
```

半个字符的溢出就会让整行折成两行，下划线跟着断成两截。

### 问题四：长题目折行后错位

题目超过一行时，折行后的文字要跟**填充线起始位置**对齐，不是跟标签左边对齐。
用「左缩进 = 填充起点 + 悬挂缩进 = 标签宽」。

> 参考实现：`scripts/jc_thesis_format.py` 里的 `field_paragraph()` 与 `build_cover()`；
> 效果对照 `reference/pages/p01.png`。

## 2. 中文字体必须显式声明

只设 `font.name = '宋体'` 只会写到 `w:ascii` 和 `w:hAnsi`，**中文会回落成 Word 默认字体**
（通常是等线/Calibri）。必须另外写 `w:eastAsia="宋体"`。

在 Word 界面里对应的是`开始 → 字体`对话框里的**「中文字体」**和**「西文字体」是两个独立下拉框**——
只改一个，另一半不生效。这是「明明设了宋体，打印出来中文还是黑乎乎另一种字」的原因。

同理，黑体标题要同时设 `w:eastAsia="黑体"` 和西文 Times New Roman。

## 3. 页脚页码域必须写完整

一个 PAGE 域由**五段**构成，缺任何一段都会出问题：

```
fldChar begin → instrText " PAGE " → fldChar separate → 缓存值 → fldChar end
```

只写 `instrText` 而不写 `fldChar`，Word 会把它当成**普通文字**，
页脚会原样打印出 ` PAGE ` 这五个字符。

另外：`w:updateFields` 要设为 `true`，Word 打开文档时才会重算页码和目录。

## 4. 分节与页码

- 「起始页码」和「续前节」是**两个**设置，改了一个没改另一个，页码就会接着上一节数。
  要重新从 1 开始，**必须取消勾选「续前节」**。
- 每节的页眉/页脚默认「链接到前一节」。封面页脚留空时，
  如果后续节的页脚还链接着前一节，会一起变空。
- **三节结构**：封面（不编号）/ 前置部分（大写罗马）/ 正文（阿拉伯从 1）。
  少一节就没法实现三种页码格式。
- 判断分节符位置：打开 `¶` 标记，分节符显示为一条带「分节符（下一页）」的双虚线。

## 5. XML 层面的两个硬约束

如果走脚本路线改 docx，这两条必须守：

1. **`w:pPr` 的直接子元素顺序是法定的**。例如 `w:spacing` 必须排在 `w:ind` 之前，
   `w:jc` 在 `w:ind` 之后。顺序错了 Word 会直接报「文档已损坏，无法打开」，
   而且报错信息不会告诉你哪里错了。
2. **`w:tblBorders` 的子元素顺序固定为**
   `top → left → bottom → right → insideH → insideV`。

> 参考实现：`jc_thesis_format.py` 里的 `ppr_set()` 会按法定顺序插元素，
> `PPR_ORDER` 常量就是那张顺序表。

## 6. 三线表

- **表头下那条线要加在表头单元格的 `w:tcBorders/w:bottom`**，
  不要用表格级的 `insideH`——后者会给**每一行**都画线，变成网格表。
- 线宽单位是**八分之一磅**：1.5 pt → `sz="12"`，0.75 pt → `sz="6"`。
  在 Word 界面里 `设计 → 边框和底纹 → 宽度` 直接选「1.5 磅 / 0.75 磅」。
- 若从 Excel 粘贴表格，会带一堆单元格底纹和直接格式。先「选择性粘贴 → 只保留文本」，
  再套三线表样式，比清理粘贴结果快。
- 跨页长表格记得设**重复标题行**，否则第二页没有表头，评审一定会提。

## 7. 目录

- **目录条目的样式 styleId 必须是 `TOC1` / `TOC2` / `TOC3`**，
  Word 的目录域才会把条目套上去。叫「目录1」之类的自定义名字不认。
- 只收三级：域代码是 `TOC \o "1-3" \h \z \u`。
- **页码只有在真正的排版引擎里才算得出来**。用 python 脚本往文档里塞目录域时，
  只能塞进「条目名 + 制表符」的**缓存值**，页码是假的。
  必须用 Word 打开、更新域、再保存：

  ```python
  word = win32com.client.Dispatch('Word.Application')
  doc = word.Documents.Open(path)
  doc.Fields.Update()
  for toc in doc.TablesOfContents:
      toc.Update()
  doc.Repaginate()
  doc.Save()
  ```

  > 参考实现：`scripts/refresh_and_export.py`
- **不要用 WPS 做这一步**。WPS 的 COM 接口（`KWPS.Application`）域更新不完整，
  目录页码常常只更新一部分。
- 定稿前最后一步永远是：`Ctrl+A → F9 → 更新整个目录`，然后**自己翻一遍目录页码**。

## 8. 排版的工作顺序（很重要）

**在旧文档上逐处调格式，比重新排一遍更慢。** 原因：

- 旧文档里到处是**直接格式**（run 级 `w:rPr`），它的优先级高于样式。
  你把样式改成宋体小四，那些直接设为 11 pt 的 run 纹丝不动。
- 手工刷格式刷几百处，漏掉一处就前功尽弃，而且看不出漏没漏。

**推荐顺序**：

1. 以旧文档为**内容源**，用脚本把段落按类型分类（章标题 / 节标题 / 正文 / 图题 / 表题 / 表格）。
2. 新建一个干净文档，先建样式，再按分类把内容**重新排**进去。
3. 用 Word 渲染出来逐页比对，修正细节。

> 参考实现：`scripts/build_template.py` 是「建结构」的部分；
> 把真实论文灌进去的部分按同样思路写一个自己的 `build.py` 即可。

## 9. 校验闭环（不能省）

python-docx 只能看 XML，看不出「下划线被吞掉」「表格线画错行」「分页把表格切成两半」
这类问题。**必须渲染成 PDF 再看。**

```
生成 docx
  → Word COM：更新域 + 另存 PDF
  → PDF 逐页转 PNG
  → 拼缩略图肉眼看整体，放大看细节
  → 提取每页页眉/页脚文本，程序化核对页码
```

```bash
python scripts/refresh_and_export.py 论文.docx --raster   # 一步做完前三步
```

**页码核对**可以自动化：把 PDF 每页底部 70 px 的文字抽出来打印，
一眼就能看出「前置部分罗马数字 / 正文阿拉伯数字」有没有对。

## 10. 格式 vs 内容的边界

格式统一的时候，一定会看到内容问题。**列出来交回作者，不要顺手改**：

| 常见内容问题 | 处理 |
|---|---|
| 题注号写错（图号配了表格） | 记录位置，交回作者确认是改号还是改对象 |
| 同一图号/表号出现两次 | 同上 |
| 章节整段是占位符`【此处填写…】` | 保留占位符，只在末尾汇总提醒 |
| 正文引用标注与参考文献表对不上 | 交回作者，不要自作主张删条目 |
| 参考文献格式不统一（有的是 GB/T 7714，有的不是） | 统一成 GB/T 7714 属于格式，可以做；但作者名、年份写错不能改 |

处理这些的理由很简单：你无法判断作者的本意是「编号写错了」还是「该放表格却放了图」。

## 11. 症状对照表（出问题时先查这里）

| 症状 | 最可能的原因 | 去哪一节 |
|---|---|---|
| 封面下划线右半段消失 | 行尾空白的下划线被吞 | §1 |
| 封面字段行折成两行 | 填充宽度没向下取整 | §1 |
| 中文不是宋体（或不是黑体） | 只设了西文字体，没设 `w:eastAsia` | §2 |
| 页脚打印出 ` PAGE ` | 域只写了 instrText，没写 fldChar | §3 |
| 正文第一页页码是 7 而不是 1 | 第 3 节还勾着「续前节」 | §4 |
| 封面出现页码 | 封面没有独立成节 | §4 |
| 改样式后部分段落没变 | 那些段落有直接格式压着 | §8 |
| 目录页码全是错的 | 没有用 Word 更新域 | §7 |
| Word 报「文档已损坏」 | `w:pPr` / `w:tblBorders` 子元素顺序错了 | §5 |
| 表格每一行都有横线 | 用了表格级 `insideH` 而不是单元格 `bottom` | §6 |
| 表格线太粗/太细 | 单位是八分之一磅，1.5 pt = sz 12 | §6 |
| 标题是蓝色斜体 | Word 内置 Heading 样式自带主题色，没改回黑色 | 见 `format-checklist.md` §4 |
| 目录里冒出副标题 | 副标题被设成了标题样式 | 见 `format-checklist.md` §5.2 |
